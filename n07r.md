# Problem 7: strings that end with `10`

**Language:** {s | s ends with 10}, over Σ = {0, 1}

## NFA and batch run

![NFA and batch run for #7](n07_batch.png)

## Design

| State | Meaning | on 0 | on 1 |
|---|---|---|---|
| A (start) | still reading, nothing committed | {A} | {A, B} |
| B | guessed that the 1 just read is the 2nd-to-last symbol | {C} | none |
| C (accepting) | just read `10` and the input ended | none | none |

The NFA guesses where the end of the string is. Every time it reads a 1, A splits into a thread that stays in A and a thread that goes to B. C has no outgoing edges, so a thread that reaches C only survives if the input ends right there.

## Test strings (`n07t.txt`)

| String | Expected | JFLAP result |
|---|---|---|
| `10`, `010`, `110`, `0110`, `1010` | accept | accept |
| `0`, `1`, `01`, `11`, `100`, `101` | reject | reject |

`101` and `100` are the corner cases: the string contains `10`, but it does not end with it.
