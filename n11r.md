# Problem 11: the 2nd-to-last bit is 1

**Language:** {s | the 2nd-to-last bit of s is 1}, over Σ = {0, 1}

## NFA and batch run

![NFA and batch run for #11](n11_batch.png)

## Design

| State | Meaning | on 0 | on 1 |
|---|---|---|---|
| A (start) | still reading | {A} | {A, B} |
| B | guessed that the 1 just read is the 2nd-to-last bit | {C} | {C} |
| C (accepting) | read exactly one more symbol after the guessed 1 | none | none |

## Test strings (`n11t.txt`)

| String | Expected | JFLAP result |
|---|---|---|
| `10`, `11`, `010`, `011`, `0010` | accept | accept |
| `0`, `1`, `01`, `00`, `100`, `101`, `1101` | reject | reject |

## Step-through of `1101` (reject)

| After reading | Active states |
|---|---|
| (start) | {A} |
| `1` | {A, B} |
| `11` | {A, B, C} |
| `110` | {A, C} |
| `1101` | {A, B}, no C, so reject |

## What I noticed

Reaching C early does not mean the string is accepted. A thread in C only counts if the input ends at that moment. In `1101` a thread reaches C after the second and third symbols, but the last 1 kills it, because C has no outgoing edges.
